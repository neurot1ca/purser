Resolve and run the bundled Purser binary as in `commands/optimize.md`, using the `init` subcommand. Pass the existing arguments unchanged:

```bash
os="$(uname -s)"
arch="$(uname -m)"
case "$os" in MINGW*|MSYS*|CYGWIN*) os=windows ;; Darwin) os=darwin ;; Linux) os=linux ;; *) echo "Unsupported OS: $os" >&2; exit 1 ;; esac
case "$arch" in x86_64) arch=amd64 ;; aarch64) arch=arm64 ;; amd64|arm64) ;; *) echo "Unsupported architecture: $arch" >&2; exit 1 ;; esac
suffix=""; [ "$os" = windows ] && suffix=".exe"
"${CLAUDE_PLUGIN_ROOT}/bin/purser-hook-${os}-${arch}${suffix}" init --detect --json
```

1. Show which agents are installed and the current roles, trust, and profile state from the bundled binary's `init --detect --json` output in the current project. Read `maintenance_enabled`: `null` means no project choice has been saved; `true` or `false` means the user has already chosen, so do not offer maintenance again.
2. Tell the user in one sentence, in bold, that Purser learns as it works in this project: it measures how long its work really takes, sharpens its estimates, and points out where tokens and time can be saved. In the same bold intro, add this approved text in the user's language: "It runs independent jobs at the same time, each in its own worktree; a job that would touch files another job is changing waits in the queue and starts when that one finishes. When a task needs a plan, Purser offers one first and then carries out its steps in order." Then tell the user that Claude Code is the orchestrator. Ask in the user's language: "Who writes the code? 1) Codex 2) Claude". Add "3) OpenCode (free models included)" only when detection reports OpenCode available, and "Antigravity (agy)" only when detection reports agy available. Show which agents are installed. If Codex is chosen, ask how Purser should work using this approved source text, rendered in the user's language without changing the three options or their meaning: "Purser nasıl çalışsın? 1) Dengeli (önerilen): Her iş için uygun modeli Purser seçer; kullandıkça öğrenir, zamandan ve kotadan tasarruf eder. 2) Maksimum zeka: Her işte en güçlü model ve en yüksek düşünme seviyesi; daha yavaş, kotayı daha hızlı tüketir. 3) Kendim seçeceğim: Kodlayıcının modelini ve düşünme seviyesini sen belirlersin; Purser dokunmaz." Pass the selected option as `--mode balanced`, `--mode maximum`, or `--mode manual` to both `--plan` and `--apply`. For manual mode, run the bundled binary's `init --list-models --json --coder codex`, show only its listed models, and let the user choose one. Show the chosen model's listed efforts and let the user choose one; pass the choice with `--model MODEL` and `--effort EFFORT` to both commands. Do not accept a model or effort outside the listing. If OpenCode or agy is chosen, show its detected options by model name. Group all `opencode/*-free` models and `opencode/big-pickle` under "Free OpenCode models (Purser races them)"; show each paid/provider model (including DeepSeek models) as its own option. For an OpenCode coder route, pass the exact selected model as `--model MODEL` to both commands, without `--mode`. The agy options come from `agy models` and contain only Gemini models because Reviewer-1 also runs agy. Antigravity routes use medium effort by default. If Claude is chosen, ask no mode or model question and say: "Claude writes the code and the plans. Purser picks a tier for each task and always runs its newest model: Haiku for simple and operational work, Sonnet for ordinary work, Opus for important work and plans."
3. After the coder is chosen, rerun the bundled binary's `init --detect --json --coder CODER`, adding `--model MODEL` when a specific coder model was selected. For codex, OpenCode, or agy, ask in the user's language using this exact approved wording: "Ana kodlayıcının kotası dolar ya da çalışmazsa hangi kodlayıcıya geçilsin? Geçmeden önce her seferinde sana sorulur." Show only working coders from detection, by model name, plus "Yedek yok". Never offer a fallback for Claude as primary because its dispatch boundary is not established. On a selected fallback, pass `--fallback-agent AGENT --fallback-model MODEL` to both plan and apply; for "Yedek yok", pass neither flag. Read `coder_family` and `reviewer_options` from the detection JSON. Each reviewer option has an `agent`, pinned `model`, and `family`; when `same_family` is present, use it to mark the option. If it is absent, compare the option's `family` with `coder_family` from the JSON. Ask in the user's language using this approved text, rendered without changing meaning: "Who should be the independent reviewer (Reviewer-1)?" Show the detected reviewer options by model name, plus "None". For a selected option, pass `--reviewer AGENT --reviewer-model MODEL` to both plan and apply; use `--reviewer none` for None. Say: "We strongly recommend a reviewer from a different family than the coder; same-family options are marked." If None is chosen, explain that every delegated call receives FULL review.
4. When OpenCode is detected, ask in the user's language using this approved text, rendered without changing meaning: "Mechanical chores (counting, status checks, summaries) can run on free OpenCode models. Purser's own racing method picks the best free model and keeps learning as it works. Turn it on?" On yes add `--opencode-mechanical`; on no add `--no-opencode-mechanical` to both plan and apply.
5. Ask whether to trust the current project and whether to scaffold `.orchestrator/profile.toml`.
6. If the repo has a UI framework in `package.json`, `.tsx`, `.vue`, `.svelte`, or `.html` files, or is empty, and neither `AGENTS.md` nor `.orchestrator` records a Ponytail decision, offer once in the user's language: "⚓ **Building UI or web screens? Purser can switch on Ponytail: shortest working code, no needless abstractions, noticeably fewer tokens on UI work.** Turn it on for this project?" On yes, copy `${CLAUDE_PLUGIN_ROOT}/addons/ponytail/ponytail.md` to `.orchestrator/ponytail.md` and add this exact line to `AGENTS.md` (create it if missing):

   > Before writing code, read `.orchestrator/ponytail.md`. The repository contract and the task's acceptance criteria outrank it.

   On no, do nothing.
7. Only when Codex is the chosen coder and `maintenance_enabled` is `null`, after the existing setup questions and before showing the plan, ask once in the user's language using this approved master, rendered without changing meaning or option order:

   > ⚓ **Purser can keep this project tidy in the background.**
   > *When you are idle, it runs read-only scans (cleanup candidates, missing tests) through your Codex subscription quota, never on a paid API, and never while a job is running. It changes nothing; you get a short report to act on.*
   > *Turn it on for this project? (1-yes (recommended) 2-no) You can change this anytime with `/purser:optimize`.*

   On yes, add `--maintenance` to both the plan and apply commands; on no, add `--no-maintenance` to both. If Codex was not chosen, do not ask and pass neither flag.
8. Run the bundled binary's `init --plan --coder X --reviewer AGENT`, adding the selected `--mode MODE` and manual `--model MODEL --effort EFFORT` only when Codex was chosen, or coder `--model MODEL` only when OpenCode or agy was chosen. For a selected Reviewer-1 model, add `--reviewer-model MODEL`. Use `--reviewer none` when None was selected. Pass the selected mechanical-route flag when OpenCode was detected. Add `--trust` and `--scaffold-profile` only if chosen. Include the selected maintenance flag when Codex was chosen. Show the entire plan, including its resolved route-to-model/effort pairs. Ask for explicit yes to this exact plan. Only after that yes, run the same options with `--apply --json` instead of `--plan`. After a successful apply, if the user opted into maintenance in step 7, immediately run the bundled binary's existing synchronous cleanup command: `"${CLAUDE_PLUGIN_ROOT}/bin/purser-hook-${os}-${arch}${suffix}" maintenance run cleanup --repo "<repository-root>"`. It saves the report and the cleanup `last-run.json` marker as part of the run, so the scheduler will not rerun cleanup for 56 hours. Read the report path printed by the command and present its findings in the same concise form as the SessionStart maintenance notice: finding count, the top five findings and evidence in a table, and the full report path (the full report retains any remaining findings). If the command fails, show the error and stop setup. If the JSON reports `concise_style_offer_due: true`, ask in the user's language and wait for 1 or 2, using exactly these approved lines (render the second line in italics):

   Turkish:

   > Purser'ın ölçümlerinde kısa yanıtlar ortalama %56 daha az çıktı tokenı kullandı. Senin için Concise cevap stilini açayım mı? Endişelenme, istediğin zaman yine uzun cevap isteyebilirsin. (1-evet 2-hayır)
   > *Güvenlik ayarların izin vermezse, ayarı senin açman için haber vereceğim.*

   English:

   > In Purser's measurements, concise replies used 56% fewer output tokens on average. Shall I turn on the Concise reply style for you? Don't worry, you can still ask for longer answers anytime. (1-yes 2-no)
   > *If your security settings don't allow it, I'll let you know so you can turn it on yourself.*

   On 1, run the bundled binary's `init --enable-concise-style`. If it is denied or fails, tell the user in their language: "Ayarı açamadım; `/output-style concise` yazarak sen açabilirsin." / "I couldn't change the setting; type `/output-style concise` to turn it on yourself." On 2, continue; declining still counts as shown.
9. Run `/purser:check` and show its result.
10. Offer `/purser:optimize` in one sentence; do not run it automatically.

Never edit `~/.orchestrator/config.toml` or `.orchestrator/profile.toml` by hand. If detection or planning fails, show the error and stop setup.
