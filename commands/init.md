2. Tell the user in one sentence, in bold, that Purser learns as it works in this project: it measures how long its work really takes, sharpens its estimates, and points out where tokens and time can be saved. Then tell the user that Claude Code is the orchestrator. Ask in the user's language: "Who writes the code? 1) Codex 2) Claude". Add "3) OpenCode (free models included)" only when detection reports OpenCode available, and "Antigravity (agy)" only when detection reports agy available. Show which agents are installed. If Codex is chosen, ask how Purser should work using this approved source text, rendered in the user's language without changing the three options or their meaning: "Purser nasıl çalışsın? 1) Dengeli (önerilen): Her iş için uygun modeli Purser seçer; kullandıkça öğrenir, zamandan ve kotadan tasarruf eder. 2) Maksimum zeka: Her işte en güçlü model ve en yüksek düşünme seviyesi; daha yavaş, kotayı daha hızlı tüketir. 3) Kendim seçeceğim: Kodlayıcının modelini ve düşünme seviyesini sen belirlersin; Purser dokunmaz." Pass the selected option as `--mode balanced`, `--mode maximum`, or `--mode manual` to both `--plan` and `--apply`. For manual mode, run `purser_init.py --list-models --json --coder codex`, show only its listed models, and let the user choose one. Show the chosen model's listed efforts and let the user choose one; pass the choice with `--model MODEL` and `--effort EFFORT` to both commands. Do not accept a model or effort outside the listing. If OpenCode or agy is chosen, show its detected options by model name. Group all `opencode/*-free` models and `opencode/big-pickle` under "Free OpenCode models (Purser races them)"; show each paid/provider model (including DeepSeek models) as its own option. For an OpenCode coder route, pass the exact selected model as `--model MODEL` to both commands, without `--mode`. The agy options come from `agy models` and contain only Gemini models because Reviewer-1 also runs agy. Antigravity routes use medium effort by default. If Claude is chosen, ask no mode or model question.
3. After the coder is chosen, rerun `purser_init.py --detect --json --coder CODER`, adding `--model MODEL` when a specific coder model was selected. For codex, OpenCode, or agy, ask in the user's language using this exact approved wording: "Ana kodlayıcının kotası dolar ya da çalışmazsa hangi kodlayıcıya geçilsin? Geçmeden önce her seferinde sana sorulur." Show only working coders from detection, by model name, plus "Yedek yok". Never offer a fallback for Claude as primary because its dispatch boundary is not established. On a selected fallback, pass `--fallback-agent AGENT --fallback-model MODEL` to both plan and apply; for "Yedek yok", pass neither flag. Read `coder_family` and `reviewer_options` from the detection JSON. Each reviewer option has an `agent`, pinned `model`, and `family`; when `same_family` is present, use it to mark the option. If it is absent, compare the option's `family` with `coder_family` from the JSON. Ask in the user's language using this approved text, rendered without changing meaning: "Who should be the independent reviewer (Reviewer-1)?" Show the detected reviewer options by model name, plus "None". For a selected option, pass `--reviewer AGENT --reviewer-model MODEL` to both plan and apply; use `--reviewer none` for None. Say: "We strongly recommend a reviewer from a different family than the coder; same-family options are marked." If None is chosen, explain that every delegated call receives FULL review.
4. When OpenCode is detected, ask in the user's language using this approved text, rendered without changing meaning: "Mechanical chores (counting, status checks, summaries) can run on free OpenCode models. Purser's own racing method picks the best free model and keeps learning as it works. Turn it on?" On yes add `--opencode-mechanical`; on no add `--no-opencode-mechanical` to both plan and apply.
5. Ask whether to trust the current project and whether to scaffold `.orchestrator/profile.toml`.
6. If the repo has a UI framework in `package.json`, `.tsx`, `.vue`, `.svelte`, or `.html` files, or is empty, and neither `AGENTS.md` nor `.orchestrator` records a Ponytail decision, offer once in the user's language: "⚓ **Building UI or web screens? Purser can switch on Ponytail: shortest working code, no needless abstractions, noticeably fewer tokens on UI work.** Turn it on for this project?" On yes, copy `${CLAUDE_PLUGIN_ROOT}/addons/ponytail/ponytail.md` to `.orchestrator/ponytail.md` and add this exact line to `AGENTS.md` (create it if missing):

   > Before writing code, read `.orchestrator/ponytail.md`. The repository contract and the task's acceptance criteria outrank it.

   On no, do nothing.
7. Run `python "${CLAUDE_PLUGIN_ROOT}/.claude/hooks/orchestrator/purser_init.py" --plan --coder X --reviewer AGENT`, adding the selected `--mode MODE` and manual `--model MODEL --effort EFFORT` only when Codex was chosen, or coder `--model MODEL` only when OpenCode or agy was chosen. Add `--trust` and `--scaffold-profile` only if chosen. Show the entire plan, including its resolved route-to-model/effort pairs. Ask for explicit yes to this exact plan.
